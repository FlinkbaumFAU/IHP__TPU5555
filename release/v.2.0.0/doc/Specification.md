# TPU5555 – Specification

## Function

TPU5555 implements a hyperdimensional-computing (HDC) classifier with on-chip training:

- **Encoding.** Each of the N=32 features is quantized to one of M=40 levels:
  `level = round(feature·(M−1)/32768)`. Its level hypervector (continuous memory, CM) is
  XOR-bound with the position hypervector (item memory, IM). The 32 bound vectors are
  bundled bit-wise by majority (`count ≥ N/2`). The computation runs chunk-serially,
  40 bits at a time, for D=1000 bits.
- **Training.** Each bit of the encoded vector adds ±1 to an 11-bit signed counter for
  the current class. A finalize writes sign(counter) into associative-memory (AM) row
  `label` and clears the counters.
- **Inference.** The chip computes the Hamming distance (XOR + popcount) to every AM row
  and returns the argmin as the class (3 bit).

Separately, an **MDLL** (instance `i_mdll`, hard macro `mdll`) multiplies the clock on
`pad_mdll_clk_ref` by 4. It is a test structure with its own pads and no connection to the
classifier logic (datasheet, *MDLL test structure*; sources and design notes in
`TPU5555-main/mdll/`).

## Block diagram

```
pads ─ spi_slave ─ hdc_spi_loader ─ hdc_cmd_loader ─ Accelerator
                                                      ├─ IdentityMemory    (IM, 32×1000 b)  SRAM 1024x32 + 1024x8
                                                      ├─ ContinousMemory   (CM, 40×1000 b)  SRAM 1024x32 + 1024x8
                                                      ├─ AssociativeMemory (AM,  8×1000 b)  SRAM 256x48
                                                      ├─ ClassCounterRAM   (1000×11 b)      SRAM 1024x16
                                                      └─ majority buffer   (25×40 b flops)

pads ─ mdll (hard macro: DCO, TDC, bang-bang PD, lock_ctrl) ─┬─ code[7:0], locked ─ pads
                                                              └─ clk_out ─┬─ pad (raw)
                                                                          └─ /4 counter ─ pad
```

## Hierarchy and naming

| View | Top name |
| --- | --- |
| RTL (VHDL) | `hdc_chip_top` (`TPU5555-main/rtl/asic/hdc_chip_top.vhdl`), core instance `i_core` = `hdc_word40_top` |
| GDS, netlists (CDL, Verilog), DEF, LIB, SDF, SPEF | `TPU5555` |
| MDLL macro (all views) | `mdll`, instance `i_mdll` |

The RTL top name was kept so the LibreLane flow under `TPU5555-main/Flow/` runs unchanged.
The layout and netlists were renamed to `TPU5555` after the flow run. `make_release.py` renames the top cell and corrects the sealring area label. KLayout `LayoutDiff` shows those are the only changes, and all physical checks were re-run on the result (see `release/v.2.0.0/doc/Signoff.md`).

## Clocks and timing

| Clock | Period | Notes |
| --- | --- | --- |
| `clk` | 20 ns | System clock |
| `sclk`, `cs_n` | 100 ns | SPI front end; asynchronous to `clk`, with toggle synchronizers |
| `mdll_ref` | 10 ns | MDLL reference from `pad_mdll_clk_ref`; drives only the macro |
| `mdll_out` | 1.25 ns | MDLL output; clocks only the /4 counter. 4 × the reference at lock; 1.25 ns covers lock up to a 200 MHz reference. Hold uncertainty 0.05 ns (the counter captures on the edge that launched it) |

All clock groups are asynchronous to each other. Worst slacks after routing:

| Clock | Setup (slow, 1.08 V / 125 °C) | Hold (fast, 1.32 V / −40 °C) |
| --- | --- | --- |
| `clk` | +3.13 ns | +0.43 ns |
| `sclk` | +20.3 ns | +0.18 ns |
| `mdll_out` | +0.17 ns | +0.10 ns |

There are 0 slew and 0 cap violations. The 211 max-fanout entries are all CTS clock
buffers, each driving 10–16 flip-flops against a limit of 8. They are waived in
`release/v.2.0.0/doc/Signoff.md`.

## Physical implementation

- Die 2400 × 2000 µm, core [365, 365, 2035, 1635] µm, sg13cmos5l IO ring with 35 pads.
- Two macro rows (IM/CM south, counters/AM north) around a ~280 µm logic channel.
- The MDLL macro sits in the top-right corner of the core at (1735, 1260) µm, with no signal
  routing over it (its LEF blocks Metal1–Metal4, a routing obstruction TopMetal1).
- The PDN is a core ring plus a stripe grid (IHP LibreLane template), with SRAM and MDLL macro grids on Metal4↔TopMetal1.
- 207 ECO antenna diodes sit on SRAM inputs; 32 ECO hold buffers (`dlygate4sd3_1`) on the
  D pins of the SPI shift and receive registers, generated by register name
  (`Flow/scripts/LibreLane/scripts/gen_eco_buffers.py`).
- The seal ring was added by the LibreLane `KLayout.SealRing` step and fill by `KLayout.Filler`.
