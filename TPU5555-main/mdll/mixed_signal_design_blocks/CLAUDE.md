# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repo is an all-digital MDLL (the name "mixed_signal_design_blocks" is historical), targeting the **IHP SG13G2 130nm BiCMOS open-source PDK**. The **repo root is the top level**: `mdll.sch` integrates the blocks, `test_mdll.sch` is the closed-loop testbench, and the root `Makefile` builds and simulates it. The blocks are:

- **`clk_gen/`** — DCO ring, injection selector and ÷4 divider (schematic-first; the cap-bank decoder is RTL)
- **`bbpd/`** — single-flop binary phase comparator + 8-bit loop-filter accumulator (`rtl/dlf.v`)
- **`tdc/`** — Vernier time-to-digital converter for fast lock. `src/tdc.sch` is the top; its parts:
  - `tdc/osci/src/` — matched slow/fast rings, generated by `gen_osci.py` (edit that, not the `.sch`)
  - `tdc/counter/src/counter.v` — 8-bit ring counter (synthesised by `tdc/synth/`)
  - `tdc/edge_lock/` — edge-lock detector; `tdc/src/tdc_pd.sch` — the "close enough" phase detector
- **`lock_ctrl/`** — coarse-acquisition controller (`rtl/lock_ctrl.v`, hardened from its mapped netlist): forces the fastest code, turns TDC readings into code jumps, hands over to the bang-bang loop

How they connect (see `mdll.sch` and the header of `lock_ctrl.v`): clk_gen is a **gated ring** — it runs 4 DCO periods from each injection, raises `div`, then waits for the next `clk_ref`. That wait, `T_REF − 4·T_DCO`, is the frequency error. The TDC measures it (slow ring started by `div`, fast ring by `clk_ref`), but only when the ring is fast: a slow ring puts `clk_ref` first and the TDC reports `hit`. So acquisition starts at code 0x00 and under-corrects. `lock_ctrl` arms the TDC itself (its `Sel`), so a run only starts on request and the captured counts are stable when read.

**Current tape-out status and next steps: `TAPEOUT.md`** — read it before continuing that work.

The PDK is installed at `/opt/IHP-Open-PDK/`, which is also exported as the `PDK_ROOT` environment variable. The Makefiles default `PDK_ROOT ?= /opt/IHP-Open-PDK/`.

## Design Flow

Physical design uses **LibreLane**, not hand-written OpenROAD scripts. The flow tools (librelane, sta, openroad, klayout, magic, yosys) come from the nix profile on PATH; `make harden NIX_SHELL="nix develop ~/Documents/Passionate/librelane -c"` runs them from a librelane checkout's dev shell instead. clk_gen, bbpd, tdc and lock_ctrl share one Makefile shape and are hardened individually; the top level (`pnr/`, root `make macros harden`) places them as macros.

```
src/*.sch             --xschem -w-->  build/01-synth/<top>.nl.v     hierarchy
RTL (dlf.v, counter.v, dco_decode.v, lock_ctrl.v)
                      --yosys-->      build/01-synth/<rtl>.v        mapped gates, LEC-proven
both                  --common/pnr/mk_netlist.py--> <top>.pnr.v     transistor bodies stripped
that                  --pnr/prep_netlist.tcl-->     <top>.flat.v    flat, every cell `keep`
that                  --librelane pnr/config.yaml-> pnr/runs/<tag>/final/
```

LibreLane runs with `SYNTH_ELABORATE_ONLY`: the netlist arrives already mapped, so rings (deliberate combinational loops), latches and deliberately-metastable sampler flops are never re-optimised. Every block's `pnr/config.yaml` reuses the clk_gen layer/PDN recipe (Metal1–Metal3 only, PDN inset to the core, signal pins north/south) — read the comments there before changing any of it.

### SG13CMOS5L variant

The same MDLL also hardens on **ihp-sg13cmos5l** (M1–M4 + TopMetal1: no Metal5, no TopMetal2). Its standard cells are sg13g2's under another prefix (Verilog models, LEF, CDL and Liberty are identical after renaming). So the schematics, the RTL mapping and its LEC stay sg13g2, and `common/pnr/retarget.py` renames the cells in the flat netlist (`build/sg13cmos5l/<top>.flat.v`). xschem cannot do the renaming: its Verilog netlister names a cell after its symbol file. The `prefix` attribute only affects SPICE. The custom cells are reused unchanged, because the stacks are identical up to Metal4. Each `pnr/config.yaml` holds the differences in a `"pdk::ihp-sg13cmos5l":` section. LibreLane applies such a section where it stands, so a key set further down overrides it: keep it last when it overrides layers (`pnr/config.yaml`). `STD_CELL_LIBRARY` is left to the PDK default for the same reason. Runs are tagged `CMOS5L_*` (sg13g2: `RUN_*`), and the root `macros_cmos5l` copies them to `build/sg13cmos5l/macros/`. `--manual-pdk`: ciel has no CMOS5L, so it comes from `build/pdk_cmos5l`, which `common/pnr/cmos5l_pdk.sh` builds: `$PDK_ROOT/ihp-sg13cmos5l` with `libs.tech/librelane` from IHP-Open-PDK 23854a19^ (that commit adopted LibreLane `dev`'s variable names, which no released LibreLane reads). See TAPEOUT.md for its LVS deck and the replica-matching result.

**`PAD_CDLS` is `common/pnr/cdl_tail.cdl` on purpose.** LibreLane 3.0.16's `KLayout.LVS` writes the concatenated CDLs to a temp file it never flushes, so the last ≤ 8 KiB are missing from the LVS reference. That file is comment padding, so only padding is lost.

## Schematics: symbol paths and `tools/xschem`

**Every project symbol is referenced relative to the repository root**
(`clk_gen/src/dco.sym`, `bbpd/src/pd.sym`, `tdc/counter/src/counter.sym`), and
**xschem must be launched through `tools/xschem`**.

Both halves are required. xschem resolves a symbol reference against the
entries of `XSCHEM_LIBRARY_PATH` — *not* against the directory of the schematic
that names it. A bare `src/dco.sym` therefore means "whichever directory on the
path happens to have a `src/`", which depends on the working directory xschem
was started in: descending from `bbpd/test_fine_loop.sch` into `clk_gen` used to look
for clk_gen's sub-symbols under `bbpd/` and fail. Root-relative references are
unique repo-wide, so there is no ambiguity and no risk of silently picking a
same-named symbol from another block.

`tools/xschem` discovers the repo root from its own location, exports it as
`MSDB_ROOT` and as `XSCHEM_USER_LIBRARY_PATH` (which the user's `xschemrc`
appends to `XSCHEM_LIBRARY_PATH`), makes any path arguments absolute, and runs
xschem **from the root**. Running from the root matters on *save* too: xschem
rewrites symbol paths relative to the working directory, so editing from
anywhere else would quietly un-qualify them again.

No absolute paths are stored in any `.sch` file, so the checkout stays portable.

```sh
tools/xschem bbpd/test_fine_loop.sch      # from the repo root
../tools/xschem test_fine_loop.sch       # or from inside a block -- same result
```

The Makefiles already use it (`XSCHEM := $(ROOT)/tools/xschem`); prefer
`make build/test_fine_loop.spice` over calling xschem by hand.

### Paths inside SPICE code blocks

A testbench's `.INCLUDE` and `write` paths cannot be relative, because the two
ways of running a deck have different working directories: `make` runs ngspice
from the block directory, while xschem's *Simulate* button runs it from
`netlist_dir`, which `xschemrc` derives from `$PWD` — and `tools/xschem` has
made that the repo root.

They are made absolute at netlist time instead. xschem runs a `code_shown`
`value` through tcl `subst` when the whole attribute is wrapped in
`tcleval(...)`, so the schematic can store `$env(MSDB_ROOT)/...` and the netlist
comes out with a real path. The `.sch` still holds no absolute path.

Three things to know before editing such a block (`bbpd/test_fine_loop.sch` is the
worked example):

- **A failed `tcleval` replaces the entire block with a single `?`, silently** —
  xschem catches the tcl error and exits 0, same class of trap as `IS MISSING`.
  `bbpd/Makefile` greps for it.
- **A literal `$` or `[` anywhere in the block is a tcl error**, comments
  included. Brackets cannot be escaped: xschem's property reader turns both
  `\[` and `\\[` back into `[` before tcl sees them. So a block that must name
  bus bits (`save C[7] ...`) cannot be `tcleval`'d at all — hand the path to it
  as an ngspice variable set from a `.control` block in the header instead, and
  use `setcs`, not `set`, because `set` lower-cases its value.
- **`tcleval` can also run commands**, which is how the Netlist button picks up
  non-schematic dependencies. `test_fine_loop.sch` shells out to
  `make -C bbpd simulations/dlf.spice` and prints the return code as a comment,
  because that include is a yosys output the GUI would otherwise never rebuild.

**When xschem cannot resolve a symbol it writes `IS MISSING` into an otherwise
plausible `.subckt` and still exits 0.** That once produced a deck with no DUT
which simulated to a flat 0.665 V and looked exactly like a dead ring
oscillator. `bbpd/Makefile` greps for it rather than trusting the exit code.

## Common Commands

Block commands run from the block directory (`cd clk_gen`, `cd bbpd`, `cd tdc`, `cd lock_ctrl`).

```sh
make netlist          # xschem export + RTL synthesis + mk_netlist + flatten
make lec              # SAT equivalence of the synthesised RTL against its source
make harden           # LibreLane; results in pnr/runs/<tag>/
make sim              # the block's SPICE acceptance checks (see the Makefile)
make clean            # removes build/
make harden_cmos5l    # the same on ihp-sg13cmos5l (common/pnr/cmos5l.mk); runs pnr/runs/CMOS5L_*
```

Block-specific: `clk_gen` has `sim_decode` (iverilog decoder testbench),
`char` (DCO period sweep + monotonicity gate, also `sim`) and `test_clk_gen`
(runs the xschem testbench); `bbpd` has `formal` (BMC of the accumulator), `pd_sim`, `fine_loop_sim`
(closed loop with clk_gen), `meta_char` (flop resolution time tau, tt/ss); `tdc` has `sim_rtl` (verilator counter testbench),
`osci_sim` (ring periods and LSB at ss/tt/ff), `tdc_sim` (transfer curve,
capture race margin) and `test_tdc` (runs the xschem testbench); `lock_ctrl`
has `synth`, `lec`, `formal` (BMC with the real dlf closing the loop) and
`sim_acq` (the real lock_ctrl + dlf RTL against behavioural clk_gen/pd/TDC
models, swept over PVT scale, TDC LSB, injection delay and t_buf — milliseconds) and `sim_variants` (the same testbench with design variants and fault injection, `simul/sweep_variants.py`).

From the repo root:

```sh
make mdll_sim         # transistor-level closed loop, reset to lock (hours) + simulations/check_mdll.py
make mdll_mixed_sim   # same loop, lock_ctrl + dlf in Verilator (d_cosim), ~6x faster; CORNER=typ|slow|fast
make acq_char         # open loop: what the TDC measures vs. code (simulations/char_acq.py)
make models           # rebuild every generated SPICE model, delegating to the blocks
make macros harden   # top-level macro from each block's latest pnr/runs/*/final/ (pnr/config.yaml)
make match_report    # div vs. clk_ref_g arrival at the tdc/bbpd pins, post-layout; re-run after any re-harden
make macros_cmos5l harden_cmos5l match_report_cmos5l   # the same on ihp-sg13cmos5l
make calibre_cdl     # LVS reference CDL for Calibre (no filler instances); calibre_cdl_cmos5l likewise
make pex_sim PEX=<dir>/mdll.pex.spice [PEX_CORNER=slow]   # closed loop on a Calibre xRC netlist (days; see TAPEOUT.md)
```

`mdll_mixed_sim` (`simulations/gen_mixed.py`) swaps the structural models of
lock_ctrl and dlf for their RTL in one XSPICE `d_cosim` instance and delays each
output by the hardened block's post-PnR clock-to-output time
(`<block>/simulations/output_delays.json`, from `make -C lock_ctrl delays` /
`make -C bbpd delays` via `common/pnr/output_delays.py`; re-run after
re-hardening). It does not model setup/hold or metastability at those blocks'
inputs. `mdll_sim` stays the reference. `CORNER` picks those delays and the
matching SPICE corner together (tt 1.2 V 27 °C / ss 1.08 V 125 °C / ff 1.32 V
−40 °C: models, `VDD`, `.TEMP`, and the bridges' and `dco_decode`'s levels);
`SPICE_CORNER` overrides the latter.

Generated SPICE models of synthesised RTL (`bbpd/simulations/dlf.spice`,
`tdc/simulations/counter.spice`, `lock_ctrl/simulations/lock_ctrl.spice`) are
structural translations of the mapped netlist by `common/sim/gen_rtl_spice.py`
and are tracked; regenerate them through make, never by hand.

## Architecture Notes

- A schematic that needs a constant 0/1 must use a real `sg13g2_tiehi`/`tielo`, never `vdd.sym`/`gnd.sym`: in Verilog those netlist as undriven wires. `mk_netlist.py` fails on them.
- xschem's exit status: nonzero (10) whenever a `lab_pin` net touches only one pin. In testbenches that is normal, so the Makefiles judge testbench netlisting by the file and the greps, not the exit code. Design schematics terminate unused outputs in `noconn.sym` (see `mdll.sch`) so that a nonzero exit stays meaningful.
- **Every testbench that contains clk_gen must place `vdd.sym` and `gnd.sym`.** clk_gen's delay cells have no supply ports; they rely on xschem emitting `.GLOBAL VDD`/`.GLOBAL VSS`, which it only does when those symbols are present. Without them the ring's supplies float (~0.04 V in the operating point) and every node sits mid-rail — nothing errors.
- Every deck sets `.OPTIONS KLU` right after its model `.LIB` line (testbench headers and the `char_*`/`gen_char_*` generators). Measured on the MDLL deck: 2.4x, all of it from matrix factorisation. New decks should do the same. KLU is less forgiving of a marginal operating point: the mixed MDLL deck once failed its OP ("singular matrix" on internal flop nodes, "Transient op failed") after an unrelated one-flop change, and converged without KLU or with `.OPTIONS RSHUNT=1e12`, which `gen_mixed.py` now adds. Try that first if another deck's OP starts failing.
- **`div` and `clk_ref_g` must stay structurally identical.** The tdc and the bbpd compare them, so any delay one has and the other lacks is a static offset in e and in the lock point. `div` leaves clk_gen through `divider.sch` x5 (lgcp_1) → x9 (buf_4), with x7 (nor2b_1) loading it; `mdll.sch` copies that as x5 → x7 → `clk_ref_g`, with x8 (nor2b_1) as the dummy load. clk_gen runs with `DESIGN_REPAIR_BUFFER_OUTPUT_PORTS: false` so LibreLane adds no buffer the copy lacks (it once did: a `buf_1` on `div` that happened to cancel bbpd's then-unbuffered 49 fF `clk_ref` pin). bbpd's `pd.sch` x6 buffers `clk_ref` for everything but the sampler, so its `clk_ref` and `div` pins load alike. Changing any of these, or re-hardening, means re-running `make match_report`.
- **bbpd updates the code ~1.2 ns after `clk_ref`, in the same cycle as its decision** (x2 on a delay chain at ~0.42 ns, dlf on `clk_dlf`). That only works because `bbpd/rtl/dlf.v` holds the code in Gray and `comp` reaches the state only through and2 -> xor2 (checked by `bbpd/synth/check_comp_cone.py` at synthesis): an unresolved `comp` then moves the code by at most +-2 LSB. Don't restructure dlf's comp path, and keep `bbpd/pnr/base.sdc`'s `set_multicycle_path 0 -setup` on the same-cycle captures, or the resizer will delay them a full period.
- **Start-up: `mdll.sch` x9..x13 release the blocks, not `resetb` directly.** clk_gen's ring starts the moment its `Resetb` releases (`sel` falls with it), so `rstb_gen` rises clk-to-q after a *rising* clk_ref edge (a normal injection); lock_ctrl and bbpd get `rstb_ctl` on the next falling edge (clk_gen's forced `sel` must not look like an injection to lock_ctrl). dlf resets to lock_ctrl's START (`RESET_CODE` in `bbpd/rtl/dlf.v` = `START` in `lock_ctrl.v`, two macros: change both; `check_mdll.py` enforces it). See TAPEOUT.md "Start-up".
- **clk_gen dithers code[1:0]**: the divider counts the run's DCO periods in Gray (`g[1:0]`), and `clk_gen/rtl/dco_decode.v` adds unit N for the last code[1:0] periods, so `div` moves in quarter steps. The path from `g` to the cap enables is single gates with one changing input (checked by `clk_gen/synth/check_dither_cone.py` at synthesis) -- a glitch there would hit a running ring node. Keep the divider a Johnson counter.
- ngspice cannot load two Verilator `d_cosim` libraries in one process: the second segfaults at load ("Duplicate value 1 in cm_irreversible()"), even with `-Bsymbolic`. `gen_mixed.py` therefore builds one library for all co-simulated blocks and joins them over `.GLOBAL` nodes, which only works while each is instantiated once.
- ngspice evaluates the PDK's OSDI models multithreaded and ignores `OMP_NUM_THREADS`. Parallel sweeps must cap it per deck with `set num_threads=N` in `.control` before `tran` (see `simulations/char_acq.py`), or they oversubscribe the machine.
